# 13. Стратегия GPU-восстановления seed (26.1–26.3)

Всё ниже — синтез. «Измерено» = запущено здесь (RTX 4080 SUPER, 80 SM/10240 ядер, nvcc 12.0 sm_89, Ryzen 5 5500 12 потоков); «оценка» = расчёт/экстраполяция.
Код и результаты: `crack/experiments/` (`mcrand.h`, `c/selftest.c`, `cuda/struct48.cu`, `java/GameRef.java`, `vectors/`, `results/`).

## 0. Главные факты (проверены по исходникам 26.1/26.2/26.3 и векторам реальной игры)

1. **Структуры, слайм-чанки, mineshaft, End pillars, стронгхолды, бедрок Nether — LCG от 48 младших бит seed** (`WorldgenRandom.setLargeFeatureWithSalt`, `seedSlimeChunk`, `EndSpikeFeature.getSpikesForLevel`, `ChunkGeneratorStructureState.generateRingPositions`, legacy random Nether). 965 векторов из реального кода игры совпали с моей C-реализацией для 26.1, 26.2 и 26.3; файлы векторов идентичны побайтово => эти части **не менялись** между 26.1 и 26.3 (26.3 переписала плотности/шум, но не эти RNG).
2. Overworld-биомы, декорирование (1.18+), бедрок Overworld — Xoroshiro128++ от **64-битного** seed: прямого «LCG-взлома» нет. Мост 48 -> 64 бит: верхние 16 бит = 65536 кандидатов на structure seed, проверяются hashed seed (SHA-256, дёшево), декоратором или биомами (док. 10 §3.4).
3. Поэтому конвейер всегда: **наблюдения -> structure seed (48 бит, GPU) -> 2^16 world seed -> проверка (hashed/biome/decorator)**.
4. `abandoned_camp` (26.3, salt 91231127, 37/8) — новый структурный набор; его нужно добавить в таблицы (у cubiomes/SeedcrackerX его нет).

### Где нужна LLL/BKZ (CPU), а где хватает перебора
* LCG единственного seed без регионального сложения (стронгхолд: `Random(W).nextDouble` подряд; пиллары; любые «подряд идущие вызовы одного Random»): решётка размерности n = число измеренных вызовов (+1 или +2 на `nextInt(n)` не степени двойки — `addModuloMeasuredSeed`), строки `[MULT^(i-i0) mod 2^48 | 0…]`, последняя `[2^48]`; масштабирование по ширине интервалов (`lcm`), LLL (delta 0.99), затем перебор точек в боксе (Kannan/Fincke–Pohst). Типично n=4–12, миллисекунды на CPU. Реализация: взять схему LattiCG (`RandomReverser.java:57-150`), на C++ — NTL/fplll, в Python — `fpylll` или PARI `qflll` (PARI `gp` есть на машине).
* **Региональные структуры НЕ ложатся на одну решётку**: state_i = ((W + c_i) mod 2^48) ^ 0x5DEECE66D — XOR с константой (35 бит) не линейна по W для разных c_i. Обходы: (a) lifting младших бит + перебор старших (реализовано, измерено); (b) фиксировать младшие 35 бит (2^35 — слишком много для решёток); (c) 2^48 на GPU. Поэтому для A решётки не нужны: 0.04 с и так достаточно.
* BKZ (блок 20–30) нужен только при n > 30 (много вызовов с узкими интервалами) — в нашем наборе атак не встречается.

## 2. Связка structure seed -> world seed -> биомы (приоритет реализации)

1. `struct48`: кандидаты W48 (список, обычно 1–4, при малом числе структур тысячи — тогда дофильтровать сибилингов ещё структурами/пиллар-сидом).
2. Проверка верхних 16 бит, **по убыванию дешевизны**: hashed seed (SHA-256 от 8 байт, ~1e9/с GPU оценка, на CPU мс) -> декораторы 1.18+ (Xoroshiro, индексы сверять по oracle) -> биомы (наш `engine/`, noise-биомы 26.x, 2^16 * k точек).
3. Если seed — «случайный», верхние 16 бит однозначно из `nextLong`-реверса (`StructureSeed.toRandomWorldSeeds`), 1–2 кандидата; при ручном seed — только пункт 2.
4. Верификация: запуск oracle (реальный код) на найденном seed по 3–5 биомам/структурам.

Важное наблюдение (измерено, `results/struct_lift_stats.txt`): число ложных кандидатов определяется не суммой номинальных бит, а «эффективной» информацией = info − max(0, lift_info − L). При 4 структурах (36 бит) — тысячи кандидатов, при 6 смешанных (54.5) — ≈0.9 в среднем, при 8 — 0. Требовать от пользователя либо >=6–7 структур, либо дополнять pillar seed / слайм-чанками.

## 3. Производительность RTX 4080 SUPER (измерено / оценка)

* Полный перебор 48-битного seed с ранним выходом, первая проверка — `nextInt(lim)` с fastmod (Lemire): **1.83e11 seed/с** (linear), **1.15e11 seed/с** (первая проверка triangular). Это ≈ 70 целочисленных инструкций/кандидат при пике ~1.3e13 инстр/с (оценка) — ядро ещё не выжато (потенциал 2–3x: 32-битные половинки вместо 64-битных умножений, тест делимости обратным к lim вместо fastmod) — оценка.
* CPU (12 потоков, наивно): 3.4e8 seed/с (измерено) — GPU быстрее в ~540 раз на этом предикате.
* Любая схема «lifting + 2^28» укладывается в десятки мс; полный 2^48 нужен только если нет ни одной liftable-структуры (ancient city, ruined portal, nether complex, abandoned camp, triangular).

## 4. Предлагаемые инструменты (CLI), по ценности/сложности

Формат файла наблюдений (расширяемый): строки `kind; arg; arg…`, `#` — комментарий. Для структур формат совместим со SeedcrackerX `StructureSave` (`имя;chunkX;chunkZ`).

1. **`crack struct`** (A, готов прототип `struct48.cu`): вход `desert_pyramid;303;364` и т.п. (типы = имена structure_set 26.x); выход — список structure seed. Режимы `--lift` (по умолчанию), `--full` (если нет liftable). Сложность: низкая.
2. **`crack lift64`** (G/H): вход `--struct-seed S --hashed H` или `--biomes file` (`x z biome_id`, 8+ точек) или `--decorator dungeon;x;y;z` -> world seed. Сложность: низкая (hashed) / средняя (биомы через `engine/`).
3. **`crack nether-bedrock`** (D): вход `x y z bedrock|other` (формат Nether_Bedrock_Cracker); порт слоёв на CUDA; выход structure seed (+world seed в режиме random). Сложность: средняя; ценность высокая (наблюдение доступно любому игроку).
4. **`crack pillars`** (B): вход `--heights 76,100,…` (10 значений от 76..103 шагом 3) + файл структур -> structure seed; GPU 2^32. Сложность: низкая.
5. **`crack slime`** (C): вход `x z slime|noslime`; lifting по биту 17. Сложность: низкая–средняя.
6. **`crack mineshaft`** (E): вход `chunkX;chunkZ` старт-чанков; полный 2^48 с ранним выходом; полезен в комбинации. Сложность: низкая.
7. **`crack stronghold`** (F): вход 1–3 позиции первого кольца -> фильтр (решётка по `nextDouble`, `RandomReverser`-подобная) для объединения с другими атаками. Сложность: средняя.
8. **`crack combine`**: объединение независимых наблюдений (структуры + слайм + mineshaft + пиллары) в один GPU-фильтр по 2^48 с упорядочиванием предикатов по селективности. Сложность: средняя.
9. (исследование) **`crack end-islands`** (I) — после проверки стоимости simplex-init; пока не рекомендуется.

Порядок реализации: 1 -> 2 -> 4 -> 3 -> 5 -> 6 -> 8 -> 7. Для всех — тесты: сначала `selftest` на `gameref-*.txt`, затем псевдо-данные с известным ответом (как `struct48 --gen`), затем сверка с oracle.

## 5. Что не сделано (честно)
Не реализованы и не измерены: CUDA-порты B, C, D, E; решёточный прототип (LLL) на псевдо-данных; отчёты chunkbase/сторонних GPU-крекеров и cubiomes (`docs/11`) — выполняются фоновыми агентами, результаты могут появиться позже. Все цифры для B–E, I выше — оценки.
