# Blender-аддон «MC Worldgen»: процедурная генерация мира Minecraft 26.x — проект

Статус: утверждён автором проекта делегированием («принимай всё сам, делай по максимуму без упрощений»). Все решения ниже приняты без дальнейших вопросов; изменения фиксируются в этом файле.

## 1. Цель и критерии успеха

Аддон Blender строит мир (или любую его область) по seed **нашей собственной реализацией той же математики**, что в игре, и показывает его настоящими блоками: правильные текстуры, формы, повороты, оттенки биомов.

Что пользователь выбирает (в стиле настроек рендера Blender — панели, ползунки, выпадающие списки):

* версия игры (26.1 / 26.2 / 26.3 / 26.4-snapshot-2, расширяемо данными), измерение (Overworld, Nether, End), пресет мира (normal / large_biomes / amplified / floating_islands / caves и всё, что есть в датапаке версии);
* **сиды раздельно**: климат и биомы, рельеф (все остальные шумы), постройки, декорации (деревья, руды-фичи, растения) — **или единый**, как в игре (по умолчанию);
* область: начальные координаты (в блоках или чанках), размер в чанках по X и Z, диапазон высот;
* слои генерации: рельеф, пещеры и каньоны, руды, декорации, постройки — включаются по отдельности;
* режим «ваниль» (все параметры по умолчанию = побитово как в игре) и режим «настройки мира» с ползунками несерийных параметров (уровень моря, масштабы шумов, плотность пещер, плотность декораций и т. д.), которые игра не даёт менять.

Критерии успеха (измеряются, а не декларируются; результаты пишутся в `docs/blender/accuracy.md`):

| Ворота | Что проверяется | Порог |
|---|---|---|
| G0 | библиотека собирается под 4 платформы; аддон загружается в Blender 4.5 LTS и 5.x (headless) | да/нет |
| G1 | каждая именованная density-функция совпадает с реальным кодом игры (oracle `df`) на ≥10⁶ случайных точек, три измерения, все пресеты, все поддерживаемые версии | 0 расхождений (бит-в-бит) |
| G2 | чанки «только заполнение шумом» (поверхность, карверы, фичи, структуры отключены датапаком) совпадают с чанками настоящего сервера | 100 % блоков на ≥256 чанков × ≥3 seed × 3 измерения |
| G3 | + правила поверхности | 100 % |
| G4 | + пещеры, каньоны, aquifer-жидкости, жилы руд | 100 % |
| G5 | + декорации: каждая фича проверена в изоляции, затем все вместе | 100 % по изолированным фичам; ≥99,9 % блоков на 64×64 чанков в сборе |
| G6 | + постройки: каждый тип структуры (позиция, форма, блоки; без содержимого сундуков и сущностей) | совпадение блоков построек ≥99,9 % |
| G7 | аддон: построение сцены 32×32 чанков | < 60 с на 12 потоках; интерактивные ползунки через пересчёт только затронутых слоёв |
| G8 | редактирование: поставить / сломать блок | < 50 мс до обновления меша чанка 16×384×16 (в C-ядре меширования — единицы мс); undo/redo; границы чанков без швов |

Если ворота не достигнуты, в отчёте пишется реальное число и причина — не «примерно».

## 2. Границы и правовая сторона

* **Ресурсы Mojang не поставляются.** Датапак, список состояний блоков, модели, blockstates, текстуры, colormaps читаются на лету из серверного и клиентского jar пользователя (скачивание: `tools/fetch_game.py` / кнопка в аддоне; принятие EULA — решение пользователя). В аддон и репозиторий они не попадают.
* **Код пишется заново** по математике и поведению алгоритмов (наши документы `docs/00–23`, чтение декомпилята как справка), без построчного переноса. Совпадение с игрой проверяется только по выходным данным.
* Не цель: освещение, сущности, содержимое сундуков, жидкости в движении, redstone, поведение при игре, генерация «старых» (до 26.1) версий.

## 3. Архитектура

```
 jar пользователя (server + client)
        │  extract (Python, один раз, кэш по sha1)
        ▼
 ┌─ pack-каталог ─────────────┐   ┌─ assets-кэш ───────────────────┐
 │ data/minecraft/**.json,nbt │   │ blockstates, models, textures, │
 │ reports/blocks.json,       │   │ colormaps → атлас + таблицы    │
 │ registries.json            │   └───────────────┬────────────────┘
 └──────────────┬─────────────┘                   │
                ▼                                 ▼
        libmcgen (C, ABI)  ──чанки(u16 состояния, биомы)──►  Blender-аддон (Python)
   генератор мира, потоки, версии                   UI · мост ctypes · меши · материалы
```

### 3.1. libmcgen (C11, без внешних зависимостей)

* **Управляется данными**, как игра: читает JSON датапака из pack-каталога (свой парсер JSON, свой inflate для NBT `.nbt`/`.mca`). Благодаря этому новые версии с изменёнными данными поддерживаются без перекомпиляции; поведение, закодированное в Java (а не в данных), реализуется в C и выбирается флагом версии (`double`-ветка 26.1/26.2, `float`-ветка 26.3+ — по `docs/04`, `docs/05`).
* Переиспользует побитно проверенный `engine/` (RNG, шумы, климат, R-дерево биомов, End).
* Состояние блока — `u16` (id из `reports/blocks.json`; в 26.3 их 35 723). Чанк — секции 16³ в порядке `[y][z][x]`; биомы — клетки 4×4×4 (`u8`); карты высот `WORLD_SURFACE`, `OCEAN_FLOOR`, `MOTION_BLOCKING`, `MOTION_BLOCKING_NO_LEAVES` (`i16[256]`).
* Потокобезопасность: `McGen` (данные) и `McWorld` (сиды+измерение, предвычисленные шумы) неизменяемы после создания; потоки работают с локальными буферами. Свой маленький пул потоков (pthreads / Win32).
* Публичный ABI (`libmcgen/include/mcgen.h`): `mcgen_open/close`, `mcgen_world_new/free(dimension, preset, McSeeds, McTweaks)`, `mcgen_generate_region(world, cx0, cz0, nx, nz, stages, threads, progress_cb, &region)`, аксессоры блоков/биомов/карт высот, реестры имён блоков и биомов, `mcgen_biome_at` (быстрый предпросмотр карты биомов без рельефа), список тонких настроек (`mcgen_tweak_list`). Регион сам считает «гало» соседей, нужное слоям (карверы 8 чанков, декорации 1–3 чанка, постройки по радиусу), и отдаёт только запрошенные чанки.
* Стадии (битовая маска): `BIOMES`, `TERRAIN`, `SURFACE`, `CARVERS`, `FEATURES`, `STRUCTURES`. Порядок и зависимости — как у цепочки статусов игры (`structure_starts → biomes → noise → surface → carvers → features`).

### 3.2. Модель сидов

В игре один 64-битный seed порождает независимые потоки. Мы раздаём его по **доменам**:

| Домен | Что берёт | Реализация |
|---|---|---|
| `climate` | шумы климата (temperature, vegetation, continentalness, erosion, ridge, shift/offset) → биомы и форма рельефа | `McSeeds.climate` инициализирует их позиционную фабрику |
| `terrain` | остальные именованные шумы (jagged, пещерные, aquifer, жилы, поверхность, глинистые полосы…) и `legacy`-источники | `McSeeds.terrain` |
| `structures` | размещение построек (random_spread, concentric_rings), генерация их частей | 48-битный LCG от `McSeeds.structures` |
| `features` | seed декорации чанка (деревья, растения, фичи руд) | `McSeeds.features` |

«Единый» seed = все четыре домена равны (побитово ваниль). Строковый seed хэшируется как в игре (`String.hashCode`).

### 3.3. Тонкие настройки (режим «настройки мира»)

Таблица `McTweak {id, label, group, type, default, min, max, soft_min, soft_max}`, значения по умолчанию воспроизводят ваниль. Реализуются как параметры слоёв, а не правка данных датапака: уровень моря; масштабы шумов климата по XZ и Y; амплитуда рельефа; «крутизна»; плотность и размер пещер; границы лавы; плотность и размер руд; плотность декораций; размер деревьев; частота построек. Любой вариант сохраняется в сцене.

### 3.4. Аддон Blender (Python, расширение 4.2+, `blender_manifest.toml`)

* **Интерфейс**: вкладка в редакторе свойств (Scene → «MC World», как вкладки Render/Output) и копия в боковой панели `N`; подпанели: Версия и мир · Сиды · Область · Слои · Настройки мира (ползунки) · Вид (оттенки, вода, LOD) · Ресурсы (пути к jar, статус кэша) · Статистика. Ползунки — `IntProperty/FloatProperty` с `soft_min/soft_max`, текстовые поля seed, выпадающие списки версия/измерение/пресет.
* **Операторы**: «Сгенерировать» (modal, фоновые потоки, прогресс и отмена), «Обновить слои» (пересчёт только затронутых стадий и перестройка затронутых мешей), «Карта биомов» (быстрый предпросмотр как изображение), «Подготовить ресурсы» (распаковка jar), «Очистить».
* **Мост**: `ctypes` к libmcgen (DLL/SO/dylib из каталога расширения под платформу); вызовы идут из пула Python-потоков (GIL при вызовах отпускается).
* **Ресурсы**: парсер `blockstates` (variants, multipart, поворот x/y, `uvlock`, веса и детерминированный выбор варианта по позиции как в игре), `models` (parent-цепочки, `elements`, повороты элементов и граней, `cullface`, `tintindex`, `ambientocclusion`), сборка атласа текстур (первый кадр анимаций, `mcmeta`), colormaps (`grass`, `foliage`, `dry_foliage`) и цвета воды/тумана из JSON биомов.
* **Меши**: по секциям/чанкам, numpy-векторизация, отсечение скрытых граней по таблице непрозрачности (выводится из геометрии моделей и тегов), настоящая геометрия не-кубических блоков (ступени, плиты, заборы, растения…) из моделей, UV по атласу, цвет вершин = оттенок биома (трава/листва/вода — интерполяция по соседним биомам как в игре), отдельные материалы для непрозрачного/cutout/translucent/воды. Дальний уровень детализации (высотная карта) для больших областей. Один объект Blender на чанк-группу, коллекция на сцену.
* **Материалы**: один `Principled`-материал на слой прозрачности с атласом (`Closest`-интерполяция), vertex color для оттенка; режим «пиксельный стиль» и «гладкий».

### 3.5. Данные, меши и редактирование (строительство / разрушение)

**Принцип: блоки — это данные, а не объекты Blender.** Источник истины — массив состояний `u16` на чанк (≈196 КБ; сцена 32×32 чанков ≈ 200 МБ). Объектов-блоков нет: десятки миллионов объектов недопустимы.

* **Отображение**: один объект-меш на чанк (колонка 16×384×16; параметр «чанков на объект» 1/2/4/8 для рендера больших сцен) — геометрия объединена, скрытые грани отсечены, полностью закрытые секции пропускаются, один атлас и несколько материалов (непрозрачный / cutout / translucent / вода) ⇒ мало вызовов отрисовки.
* **Ядро меширования в C** (`libmcgen/src/mesh`): модели блоков заранее раскладываются Python-ом в таблицу «состояние → квады» (позиции, UV из атласа, `cullface`, `tintindex`, слой прозрачности, форма окклюзии), а C-ядро за один проход по чанку выдаёт массивы вершин/граней/UV/цветов для `foreach_set`. Перестройка одного чанка — единицы миллисекунд. Эталонная Python/numpy-реализация нужна только в тестах.
* **Строительство и разрушение** (модальные инструменты «Поставить» / «Сломать» / «Пипетка»): луч по мешу чанка → (блок, грань) через обратное отображение «грань → блок» (атрибут грани) → правка массива → перестройка помеченных чанков (и соседа при границе). Ориентация ставимого блока (`facing`, `half`, `axis`) берётся по виду/месту клика; «автосвязи» (заборы, панели, стены, ступени, `snowy`, плиты) пересчитываются для затронутого соседства. Правки накапливаются в разреженной таблице **слоя правок** (чанк → {локальная позиция: состояние}) и имеют собственный undo/redo-стек (нативный undo Blender с сотнями МБ данных не используем).
* **Сохранение в .blend**: меши сохраняются штатно; воксельные данные **не** сохраняются (они детерминированно воспроизводимы), сохраняются настройки генерации и слой правок. Кнопка «Загрузить воксели» заново генерирует область и накладывает правки; кэш на диске по хэшу настроек.
* **Перегенерация с правками**: смена слоёв/настроек пересчитывает затронутые стадии и накладывает правки поверх (с предупреждением, если правки оказались внутри изменившегося рельефа).
* **Оптимизации по порядку включения**: (1) отсечение граней и пропуск закрытых секций (всегда); (2) многопоточная генерация и перестройка только изменённых чанков; (3) «жадное слияние» плоских граней с повторением тайла в шейдере (быстрый вьюпорт для огромных сцен; опция); (4) дальний LOD по карте высот; (5) опция «запечь в обычный меш» (отвязать чанк от воксельных данных, чтобы редактировать вручную обычными инструментами Blender).

## 4. Проверка (ground truth)

1. **Настоящий сервер** (`run/server-26.3`, генерация чанков forceload, чтение `.mca` — `tools/l3_*`).
2. **Стадийная изоляция датапаком.** В мир кладётся датапак-переопределение: пустые `features`/`carvers`/структуры биомов, подменённый `noise_settings` (пустое `surface_rule`, отключённые aquifer/ore veins). Игра сама отдаёт «чистый» результат нужной стадии — сравниваем 100 %-но. Изоляция отдельных фич: датапак оставляет одну `placed_feature`.
3. **oracle** (`oracle/`, настоящие классы Mojang): точечные density-функции, высоты, биомы, `structstart`.
4. **Blender headless** (4.5.14 и 5.2.2): загрузка аддона, сцена, рендер превью → картинка просматривается; юнит-тесты моделей по эталонным случаям (ступень, дверь, лоза, `uvlock`).
5. Отчёты ворот G0–G7 → `docs/blender/accuracy.md`.

## 6. Потоки работ и порядок

Параллельно сразу:
* **W1 Рельеф**: загрузчик датапака и реестры, именованные шумы по доменам, VM density-функций (две численные ветки), `NoiseChunk` (интерполяция 4×8×4, кэши), aquifer, жилы руд, `BlendedNoise`, заполнение, Nether и End, пресеты → G1, G2.
* **W4 Ресурсы и меши**: парсер моделей/blockstates/текстур, атлас, оттенки, таблица «состояние → квады», **C-ядро меширования** (`libmcgen/src/mesh`), слой правок и инструменты строительства/разрушения; отлаживается на настоящих чанках из `.mca` (без движка).
* **W5 Аддон и сборка**: каркас расширения, панели/свойства/операторы, мост ctypes, кросс-сборка zig, headless-тесты Blender; сначала на предпросмотре карты биомов (готовый `engine/`).
* **W6 Эталоны**: `tools/gt/` — миры, датапак-изоляция, сравнение, отчёты; общий формат дампа чанков libmcgen для тестов.

Затем по готовности W1: **W2 Поверхность** (G3), **W3 Пещеры/каньоны/руды** (G4); затем **Декорации** (G5) и **Постройки** (G6, включая Beardifier), потом интеграция в аддон и G7.

## 7. Риски

* Объём фич (≈60 типов, 273 размещённых) и построек (≈30 типов, jigsaw, NBT-шаблоны, повороты): идёт по ворота, каждая единица принимается только по совпадению с эталоном.
* Численная бит-точность между ветками `double`/`float`: страхуется oracle-тестами G1 до написания слоёв выше.
* Память: сцена 32×32 чанков ≈ 200 МБ блоков `u16`; меш — по секциям, с освобождением.
* Версии: основной упор на 26.3; 26.1/26.2 — по различиям `docs/04`; 26.4-snapshot-2 — после стабилизации.
