# Ресурсы, меши, редактирование (поток W4)

Статус: **M1–M5 готовы**, ворота G7 и G8 пройдены (цифры ниже). Документ — контракт для W5 (аддон/UI) и отчёт W4.
Ресурсы Mojang (текстуры, модели, blockstates, colormaps) в репозиторий и аддон **не кладутся**: читаются на лету из каталога
ресурсов пользователя (`run/assets-26.3/…`, `run/pack-26.3/…`). Кураторские кадры: `docs/blender/img/render-*.jpg` (ссылки в §7).

## 1. Итог по воротам

| Ворота | Требование | Результат (Blender 4.5.14 / 5.2.2) |
|---|---|---|
| G7 | сцена 32×32 чанков < 60 с, 12 потоков | настоящие чанки libmcgen (`mcgen-cli`, 32×32, 2,90 млн граней): генерация 3,8 с + **сцена 3,5–8,7 с** (зависит от загрузки машины, см. §6); вся цепочка ≈ 7–13 с |
| G8 | поставить/сломать блок → меш чанка 16×384×16 < 50 мс | перестройка чанка (ядро + заполнение меша): **медиана 4,2–6,4 мс, p95 8–33 мс, макс. 8,5–37 мс** (шум от чужой нагрузки); ядро меширования само — **2,8 мс медиана, 4,5 мс макс.** на настоящем чанке |
| M2 | ядро ≡ эталон на случайных и реальных чанках | идентичный набор граней (позиции, UV, цвета, материал, блок, направление) на случайных мирах из всех состояний (несколько наборов опций) и на настоящих чанках; слияние граней — эквивалентно развёртке |

## 2. API для W5

### 2.1. Ресурсы (чистый Python, без bpy) — `blender/mcgen_addon/assets/`

```python
from mcgen_addon.assets import state_table
table = state_table.load(assets_dir, pack_dir, cache_dir, version=None, progress=None, force=False)   # -> StateTable
```
* `assets_dir` — `run/assets-26.3` (или сразу `…/assets/minecraft`), `pack_dir` — `run/pack-26.3` (`reports/blocks.json`, `data/minecraft/**`),
  `cache_dir` — каталог кэша: `statetable-<sha1>.npz` (ключ — SHA-1 содержимого ресурсов + версия формата; 1,0 МБ) и PNG атласа.
* `table.state_id("minecraft:oak_stairs[facing=north,…]")` (свойства в любом порядке) → id | −1; `table.state_from_props(block, props)` (недостающие
  свойства — из состояния по умолчанию); `table.state_props(id)`; `table.classify(id)` → `air|cube|partial|cutout|translucent|fluid|special|nomodel`;
  `table.describe(id)`; `table.set_biomes(biome_names, assets_dir, pack_dir)` — таблица цветов по id биомов.

### 2.2. Сцена (bpy) — `blender/mcgen_addon/render/scene.py`

```python
from mcgen_addon.render.scene import SceneBuilder, ViewSettings
sb = SceneBuilder(view_settings)        # ViewSettings | dict | любой объект с теми же именами атрибутов
sb.prepare(blocks_by_chunk, biomes_by_chunk, region_info, block_names, biome_names=None)   # ресурсы + массивы чанков, без меширования
sb.build(blocks_by_chunk, biomes_by_chunk, region_info, block_names, biome_names=None, progress=None)  # блокирующая сборка
for f in sb.build_iter(blocks_by_chunk, …):  ...  # неблокирующая: генератор, доля 0..1 после каждого чанка/группы; sb.abort() — прервать
sb.update_chunk(cx, cz) / sb.update_chunks(keys)  # пересобрать меши групп; update_chunks_iter(keys) — генератор
sb.set_lod_center(cx, cz)               # центр дальнего LOD; пересобирает группы, сменившие режим
sb.get_edit_session()                   # EditSession (§4), привязанная к массивам блоков сцены
sb.clear(full=False)
```
* `blocks_by_chunk`: `{(cx, cz): u16[height*256]}` порядок `[y][z][x]`; **не копируются** (правка массива + `update_chunk` — основной путь
  редактирования). `biomes_by_chunk`: `{(cx, cz): u8[(height/4)*16]}` или `None` (биом 0). `region_info`: `min_y`, `height` (+ `cx0, cz0, nx, nz`: тогда
  мешатся только эти чанки, остальные — контекст соседей на границах). `block_names`: имена состояний по id библиотеки (идентичная нумерация —
  без копий; иначе перекодировка по именам); `biome_names`: имена биомов по id (`None` — отсортированный список биомов pack).
* Шаг `build_iter` — не больше одного чанка меширования (в потоках) + создание одного объекта Blender (≈1–5 мс), так что модальный таймер с
  бюджетом времени не подвешивает UI.
* `ViewSettings` (все поля с умолчаниями): `assets_dir, pack_dir, cache_dir, version, chunks_per_object (1|2|4|8), biome_blend (0..7, умолч. 2),
  cutout_leaves (True), bake_shade (False), pixel_style (True: Closest), shading ('lit'|'emission'), scale (1.0), collection, threads (0 = все ядра),
  merge_flat (жадное слияние), lod, lod_distance (чанков), lod_stride (1,2,4,8,16), water_style ('TRANSLUCENT'|'OPAQUE'|'HIDDEN'),
  tint_biomes (True; False — единый нейтральный оттенок «равнин»), y_min / y_max (мировые y, включительно; блоки вне диапазона не рисуются и не
  закрывают соседей; данные не копируются и не портятся)`.
* Объекты: `mc_<gx>_<gz>` (основной), `mc_<gx>_<gz>_m` (слитые грани, при `merge_flat`), `mc_lod_<gx>_<gz>` (LOD). Атрибуты меша: `UVMap`, `Col`
  (BYTE_COLOR, область FACE = оттенок×затенение), `mc_face` (грань → чанк/блок/направление), у слитых — `Rect`. Четыре материала `MC_opaque/cutout/
  translucent/water` (+ `_tiled` и `MC_lod`); атлас — PNG в `cache_dir`, загружается как FILE-изображение.

### 2.3. Редактирование, выбор лучом — `mesh/edit.py`, `render/picking.py`, `render/edit_ops.py`

`render.register()` регистрирует операторы `mcgen.edit_place / edit_break / edit_pick / edit_undo / edit_redo` (модальные, ЛКМ — применить, ПКМ/Esc —
выход, Ctrl+Z / Ctrl+Shift+Z — undo/redo правок); `edit_ops.attach(sb)` после сборки; `edit_ops.STATE.block = 'minecraft:oak_stairs'` — ставимый блок.
Чистые функции: `tool_place(pick, view_dir_mc, block)`, `tool_break`, `tool_pick`, `tool_undo`, `tool_redo`; `picking.pick_ray(sb, origin, dir)` → `PickResult(block, face,
place, hit, state, chunk)`; `picking.pick_screen(sb, context, event)`.

### 2.4. C-ядро — `libmcgen/src/mesh/` (`mcgen_mesh.h`, `mesh.c`, ABI 3)

Один файл без зависимостей (C11, ничего не зашито: все таблицы передаёт Python), собирается вместе с libmcgen. Вызов: `mcmesh_chunk(tables, input, options, out)` →
`McMeshOutput` (SoA: `pos[n][4][3]`, `uv[n][4][2]`, `col[n][4][4]`, `mat[n]`, `block[n]`, `dir[n]`, `merged[n]`, `rect[n][4]`); `mcmesh_output_free`.
Вход — окрестность 3×3 чанков (u16) и биомов (u8 клетки 4×4×4); потокобезопасно. Опции: `CUTOUT_LEAVES, BAKE_SHADE, BLENDER_AXES, BLENDER_UV, NO_FLUIDS, NO_MODELS,
MERGE, NO_VARIANTS, NO_WATER, YRANGE (y_lo/y_hi), blend_radius, scale, y_offset`. Python-загрузчик (`mesh/mesher.py`) ищет библиотеку (MCGEN_MESH_LIB, основная
libmcgen, `lib/<платформа>/`, `libmcgen/build/mesh_test/`), пропускает устаревшие (старше исходников) и при необходимости собирает `mesh.c` локальным компилятором.

### 2.5. Сварка вершин и PBR (v0.1.14)

* **Сварка** (`mcmesh_weld` в C-ядре, `mesher.weld_quads`, вызывается из `SceneBuilder._fill_mesh`): углы четырёхугольников с одинаковой позицией (побитово, −0,0 = +0,0) получают общую вершину, одинаковые рёбра — общее ребро; грань, у которой после сварки совпали бы две вершины, не сваривается. Вершин на ≈73 %, рёбер на ≈53 % меньше (без слияния граней), память меша ≈ −30 %. Из-за общих вершин у мешей включён атрибут `sharp_face` (плоское затенение — иначе Blender усреднил бы нормали соседних граней; сам `mesh.shade_flat()` в 3–10 раз медленнее записи атрибута). Двусторонние грани (вода, листва) — два четырёхугольника на одних вершинах: `Mesh.validate()` считает их дубликатами, поэтому в тестах он не используется. Нет `mcmesh_weld` в библиотеке (или `MCGEN_NO_WELD=1`) — прежний путь, 4 вершины на грань.
* **PBR** (`assets/pbr.py`, переключатель *PBR materials*): в ванили карт нормалей и отражения нет, поэтому они строятся из атласа за ≈0,6 с (одним проходом numpy) по 46 правилам имён спрайтов; результат — два изображения размером с атлас (нормаль и orm: R — шероховатость, G — металличность, B — свечение), кэшируются PNG рядом с атласом. Нормаль — свёртка Собеля по яркости с замыканием по краям спрайта; касательное пространство OpenGL, в шейдере `Normal Map` по слою `UVMap` (для слитых граней — тот же вектор атласа, что у альбедо). Ориентацию проверяет `blender/tests/test_pbr_blender.py` (выпуклость при свете слева/сверху: освещённый склон светлее), классы и карты — `blender/tests/test_pbr.py`, граф материалов — `test_blender_scene.py`; сравнительный рендер — `blender/tests/render_pbr_showcase.py`.

## 3. Что и как считается

* **blockstates**: variants (веса; последняя подходящая запись побеждает, как `put` в игре), multipart (условия `AND/OR`, `a|b`, `!a`, числа/логика), повороты x/y/z, `uvlock`.
* **модели** (по FaceBakery/UnbakedCuboidGeometry 26.x, декомпилят клиента — только справка): цепочки parent, слоты `#имя` (в игре в грани — всегда имя слота, даже без `#`),
  `elements`, повороты элементов (ось/угол и формат x/y/z, `rescale`), UV по умолчанию и поворот грани, `cullface` (поворачивается с блоком), `tintindex`, `shade_direction_override`,
  плоские элементы (грани только по оси нулевой толщины), `uvlock` (обратное преобразование грани). Копланарные накладки (оверлей травы) приподнимаются на 0,002 блока — иначе z-fighting.
* **атлас**: первый кадр анимации (`.mcmeta`: размер кадра, порядок `frames`), спрайты «полками» в собственном размере (максимум 64 пикс.; атлас 896×884), поля 2 пикс. протяжкой краёв,
  прозрачность грани — по подобласти UV (как `SpriteContents.computeTransparency`): слой SOLID / CUTOUT / TRANSLUCENT.
* **отсечение граней** — как `Block.shouldRenderFace` (26.x): маски окклюзии граней 16×16 (из геометрии модели; `canOcclude`, `isSolid`, `skipRendering` — таблица блок-уровневых фактов
  `blockprops_data.py`, сгенерированная из настоящего кода игры (`assets/dev/BlockFacts.java`, `gen_blockprops.py`)), частичное перекрытие, листва/стекло/панели/корни/порошковый снег.
* **вариант модели по позиции**: `Mth.getSeed(x,y,z)` → `LegacyRandomSource` → `nextInt(суммарный вес)`; для multipart — `nextLong` и `setSeed` на каждую часть (как `MultiPartModel`).
  Смещение моделей (`OffsetType` XZ/XYZ, макс. смещение по блокам) — по `getSeed(x,0,z)`.
* **оттенки**: colormaps (grass/foliage/dry_foliage по температуре/осадкам), переопределения в JSON биомов, цвет воды, `grass_color_modifier` (dark_forest, swamp — шум `SimplexNoise` бит-в-бит),
  константы (берёза, ель, кувшинка, стебли, редстоун, баннеры), среднее по окну (2r+1)² (r = 2 по умолчанию, как «Biome blend»).
* **жидкости** — порт `FluidRenderer`: высоты по соседям (углы, `getHeight`), поток (`getFlow`, поворот текстуры), still/flow/overlay, обратные грани, отсечение по формам соседей.
* **особые блоки** (в игре — модель сущности): заглушки по классам `ModelPart.Cube` игры (`assets/entity_models.py`): сундуки (все виды, двойные половинки), шулкеры, баннеры (цвет флага; узоры — отдельными слоями, `render/banner_overlay.py`), черепа/головы (в т. ч. голова дракона на корабле города Края), декоративные горшки (черепки — слоями поверх боковин), статуи медного голема (4 позы × 4 степени окисления),
  корпус колокола, плоскость портала Края.
* **M5**: жадное слияние (грани-единичные квады на границе блока с UV на весь спрайт; ключ — направление, плоскость, материал, цвет, UV, порядок вершин; прямоугольники по рядам; шейдер:
  `атлас = Rect.xy + fract(local)·Rect.zw`) и LOD по карте высот (`mesh/lod.py`: ячейки stride×stride, цвет верхнего блока × оттенок биома, боковые грани при перепадах).

## 4. Редактирование (`mesh/edit.py`)

Слой правок `чанк → {индекс: (исходное, новое)}`, транзакции и свой undo/redo (глубина по умолчанию 1000), сохранение в JSON по **именам** состояний, наложение на заново сгенерированный мир с подсчётом
конфликтов. Автосвязи по правилам ванили с каскадом `updateShape`: заборы, панели/решётки, стены (low/tall/up), ступени (inner/outer), `snowy`, плиты (double), двери (петля, верх/низ),
кровати, высокие растения, ворота (`in_wall`), хорус; waterlogged. Ориентация ставимого блока по виду/месту клика (`PlaceContext.from_view`): ось, facing, half, type, face (кнопки/рычаги), rotation (знаки,
баннеры, головы). Затронутые чанки включают соседей по границе и по диагонали (углы поверхности воды) — швов нет (тест: меш после правки на границе ≡ меш с нуля).

## 6. Производительность (измерено)

Машина: 12 ядер, во время замеров загружена чужими процессами (load average 12–19), поэтому для сцен даны диапазоны; ядро и таблица замерялись вне Blender.

|---|---|

| Ядро, один настоящий чанк (в среднем 5,6 тыс. граней, макс. 9,8 тыс.) | медиана **2,8 мс**, p95 3,3 мс, макс. 4,5 мс (0,49 мкс на грань); со слиянием 3,4 мс; без жидкостей 2,2 мс |

Где было время: заполнение мешей в Blender (≈90 % сборки). Заменены медленные RNA-пути на атрибутный доступ (`position`, `.corner_vert`, `.edge_verts`, `.corner_edge`, `UVMap` как FLOAT2,

## 8. Известные отличия от игры

* **Освещение и тени** игры не воспроизводятся (свет, ambient occlusion, сглаживание): освещает сцена Blender; `bake_shade` запекает лишь направленное затенение граней (0,5/1/0,8/0,6).
* **Анимация** текстур — только первый кадр; нет анимации крышек, колокола, листвы на ветру, частиц.
* **Оттенок биомов**: берутся клетки биомов 4×4×4 чанка без «зума» BiomeManager (дрожание границ биомов); смешивание по окну 5×5 как в игре. Перемножение оттенка и текстуры происходит в линейном
  пространстве Blender (в игре — над sRGB-значениями): расхождение до нескольких процентов яркости.
* **Блоки-сущности**: заглушки без анимации, без ушей/шляпы голов, без проводника (в мире не появляется), портала Края (чёрная плоскость); у горшков не рисуется «качание», у голема — глаза (в игре статуя их не светит) и руки с предметами. Узоры баннеров рисуются слоями поверх полотна (v0.1.8): слой на каждый узор, текстура `entity/banner/<узор>.png`, цвет красителя; слои смещены на доли миллиметра, поэтому при очень малом масштабе сцены могут мерцать.
* **Форма окклюзии** выводится из модели, а не из `VoxelShape` блока (см. §5, 87,2 % состояний точно); `isFaceSturdy` для жидкости — по полному покрытию грани; лёд в правиле падающего потока не особый случай.
* **Прозрачность**: порядок сортировки полупрозрачных граней (вода/стекло) решает Blender (EEVEE: смешивание воды, остальное — dithered); могут быть артефакты на стыках стекла и воды.
* **Автосвязи**: нет выживания (растения не осыпаются, вода/лава не текут), не моделируются редстоун-связи, шипы, лозы-опоры.
* Фильтрация Closest даёт алиасинг дальних текстур (в игре — mip-карты); для гладкого вида `pixel_style=False`.

## 9. Что осталось / идеи

* Ambient occlusion углов в цвет вершин (ядро готово принять цвет по углам); LOD с текстурами и перенос LOD-слияния между чанками; слияние через границы чанков.
* Заглушки для оставшихся блоков-сущностей (проводник, шлюз Края); книга на столе зачарования.
* Сохранение слоя правок в `.blend` и «Загрузить воксели» — на стороне аддона (`EditSession.to_json / load_dict`).
