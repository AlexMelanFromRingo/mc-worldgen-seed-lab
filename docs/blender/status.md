## 2. Дорожная карта (порядок волн)

1. Волна 2 (идёт): W2 поверхность → G3, W3 карверы → G4; W1 завершает G2/версии.
2. Волна 3 — **декорации (G5)**: после G3 и G4 запустить потоки (не более 2–3 одновременно, зоны файлов разные): ядро фич (FeatureSorter, `placed_feature` модификаторы размещения, порядок шагов, `WorldGenRegion`-ограничения по границам чанков); типы фич по группам: руды/диски/блобы/озёра/источники; растительность, трава, цветы, кусты, водоросли, кораллы, лёд; деревья (стволы, листва, украшатели, грибные деревья); особые (геоды, дрипстоун, азалия, лоза, кактусы, бамбук, джунглевые, подземные); Nether и End (хор, шипы, дельты, базальт). Проверка по `features`/`feature_<id>` (изоляция по одной фиче) — 100 % изолированных, ≥99,9 % в сборе.
3. Волна 4 — **постройки (G6)**: structure_set (готовы позиции в `crack/`), старты и части построек: jigsaw (деревни, аванпосты, бастионы, города, особняки…), NBT-шаблоны (свой inflate/NBT в `libmcgen/src`), процессоры, повороты/зеркала, Java-кодированные постройки (шахты, крепости, храмы, монумент, особняк, Nether-крепость, End-город, затонувшие корабли, портал…), Beardifier/terrain_adaptation, `structure:<id>`-изоляция.
4. Волна 5 — **W7 GPU (G9)** по спеке §3.6 (CUDA: биомы → density/TERRAIN → карты высот LOD), затем интеграция в аддон и выбор устройства в UI.
5. Финал: сквозные ворота G7 на полной генерации, обновление README/документации аддона, перекрёстные версии 26.1/26.2/26.4, пакеты расширений, публикация в GitHub (по готовности вех).

## 3. Протокол автопродолжения (выполняется координатором по заданию «автопродолжение»)

Задание приходит периодически (раз в ~30 мин, пока открыта сессия Claude Code). При каждом срабатывании:
1. `git status`/`ls` не нужны для начала: сначала проверь агентов. Если список фоновых агентов недоступен напрямую — для каждого agentId из §1 со статусом «в работе»/«запущен» отправь короткий `SendMessage` «продолжай, если остановлен; если уже работаешь — игнорируй» **только если** от него давно (>40 мин) нет уведомлений и есть основания считать, что он упал по квоте. Не засыпай агентов сообщениями.
2. Если пришли уведомления о завершении агента — прочитай его итог, проверь ворота цифрами (`docs/blender/accuracy.md`, отчёты потоков), при успехе: аудит (`git grep "young-developer\|/tmp/claude"`, ELF-файлы, крупные файлы/картинки с текстурами Mojang — не публиковать), `git add -A && git commit` (сообщение по существу + строки атрибуции), обнови §1 и память (`worldgen-seed-cracking-project.md`).
3. Если закончилась волна — запусти следующую по §2 (≤4 агентов одновременно; ванильный сервер только один за раз — владеет W6; зоны файлов не пересекаются; агентам запрещены git-команды; в заданиях — ссылки на спеку, `mcgen.h`, отчёты предыдущих потоков, воротa с цифрами, правило «код пиши сам, не переписывай декомпилят построчно», «экономь токены»).
4. Публикацию в GitHub (`git push origin main`) делай на значимых вехах (G3, G4, G5, G6, релиз аддона) после аудита и обновления README (честный статус ворот).
5. Если квота исчерпана (ошибка 429 при попытке что-то сделать) — просто закончи ход без действий: следующее срабатывание повторит попытку.
6. Условие остановки: все ворота G2…G9 приняты и аддон опубликован — тогда `CronDelete` этого задания и итоговый отчёт пользователю на русском (что сделано, измеренные цифры, ограничения).
Всегда: отвечай пользователю по-русски, фиксируй только измеренное; не раскрывай секретов.
